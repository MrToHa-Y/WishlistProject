# 🎁 Ohmywishes

### Социальный сервис вишлистов и идей для подарков

Полноценное веб-приложение на **чистом PHP** (без фреймворков): каталог идей,
личные списки желаний с загрузкой фото, публичные профили, поиск друзей
и «тайное» бронирование подарков в стиле Secret Santa.

## 📖 О проекте

**Ohmywishes** — это клон-прототип сервиса вишлистов (по духу близкий к «ohmywish»):
пользователь собирает идеи подарков из каталога или добавляет свои, формирует
публичный список желаний и делится им с друзьями. Друзья могут **забронировать**
подарок, чтобы не задарить одно и то же — при этом владелец списка **не видит**,
что и кем именно забронировано (сюрприз сохраняется).

Проект написан **полностью вручную на нативном PHP 8** — без Laravel, Symfony
и прочих фреймворков, без Composer-зависимостей в коде приложения. Это делает его
отличным учебным образцом того, как устроить аккуратную, безопасную и
масштабируемую архитектуру «с нуля»: собственный роутинг через точки входа,
слой аутентификации, CSRF-защита, работа с PDO, обработка загрузок файлов
и компонентный фронтенд на SCSS + ванильном JavaScript.

> 🌐 Интерфейс полностью на русском языке. Дизайн — тёмная тема в минималистичном
> «премиальном» стиле с анимациями и адаптивной вёрсткой под мобильные устройства.

## ✨ Ключевые возможности

### 👤 Аккаунты и аутентификация
- **Регистрация и вход** с серверной и клиентской валидацией полей.
- Хеширование паролей через `password_hash()` (`PASSWORD_DEFAULT`, bcrypt).
- **Безопасные сессии**: `HttpOnly`, `SameSite=Lax`, авто-`Secure` по HTTPS,
  регенерация ID сессии при входе/выходе (защита от session fixation).
- «Умные» редиректы после входа: пользователь возвращается на ту страницу,
  с которой его попросили авторизоваться (с защитой от open-redirect).

### 💝 Желания (Wishlist)
- **Создание желания** с загрузкой собственного изображения (JPG / PNG / WEBP, до 8 МБ).
- Полный **CRUD**: редактирование названия, описания, цены, ссылки на товар и фото.
- **Сохранение идей из каталога** в свой профиль в один клик.
- **«Исполненные желания»** — отдельный раздел: желание переносится из активного
  списка в архив исполненных (и обратно) в рамках транзакции.
- Умная обработка цены: принимает `1 500,50`, `1500.5` и т.п., нормализует формат.
- Защита от дубликатов при сохранении одной и той же идеи.

### 🎅 Бронирование подарков (Secret Santa)
- Друг может **забронировать** желание в чужом публичном профиле.
- **Владелец не видит, кто забронировал** его желания — сохраняется эффект сюрприза.
- Одно желание — **одна бронь** (гарантируется уникальным индексом в БД
  и блокировкой строки `SELECT ... FOR UPDATE` внутри транзакции).
- **Автоматическое снятие брони через 90 дней** (очистка просроченных записей).
- Нельзя забронировать своё желание или снять чужую бронь.
- Раздел «Забронированные» — список подарков, которые забронировал сам пользователь.

### 🛍️ Каталог идей
- Лента готовых идей подарков с карточками, модальными окнами и промокодами.
- **Бесконечная подгрузка (infinite scroll)** через `IntersectionObserver`
  и AJAX-эндпоинт, отдающий готовые HTML-карточки порциями.

### 🔎 Профили и поиск
- **Публичные профили** пользователей с аватаром, описанием и списком желаний.
- **Виджет «до дня рождения»**: вычисляет количество дней до следующего ДР
  и показывает дату в русской локали («14 марта», «Через 3 дня»).
- **Живой поиск друзей** по username: AJAX + JSON API с debounce, отменой
  предыдущих запросов (`AbortController`) и состояниями загрузки/ошибки/пустого результата.

### ⚙️ Настройки профиля
- Смена имени, фамилии, username, описания, пола и даты рождения.
- Загрузка и удаление **аватара**.
- Смена **email** и **пароля** (с проверкой текущего пароля).
- **Удаление аккаунта** с подтверждением — каскадно удаляет все желания,
  брони и связанные загруженные файлы с диска.

### 🎨 Интерфейс и UX
- **Анимированный фон** из «парящих» подарков на страницах входа/регистрации
  (с честным учётом `prefers-reduced-motion`).
- Набор переиспользуемых **модальных окон** с единым движком анимации открытия/закрытия.
- **Flash-сообщения** (success / error / warning / info) с авто-скрытием.
- **SEO-слой**: динамические `<title>`, `description`, Open Graph-теги, управление
  индексацией (`robots`) для каждой страницы.
- Инлайн-вставка SVG-иконок прямо в разметку (возможность стилизовать через CSS).
- **Cache-busting** ассетов по `filemtime` (`?v=...`) — браузер всегда берёт свежие CSS/JS.

## 🛡️ Безопасность

Безопасности уделено особое внимание — это одна из главных «фишек» проекта:

| Механизм | Реализация |
|---|---|
| **SQL-инъекции** | Только подготовленные выражения PDO, `ATTR_EMULATE_PREPARES = false` |
| **CSRF** | Токены на все изменяющие формы, сверка через `hash_equals()`, генерация `random_bytes()` |
| **XSS** | Сквозной эскейпинг вывода хелпером `e()` (`htmlspecialchars`, `ENT_QUOTES`) |
| **Пароли** | `password_hash()` / `password_verify()`, ограничения длины (8–72) |
| **Сессии** | `HttpOnly`, `SameSite`, `Secure`, регенерация ID |
| **Загрузки файлов** | Проверка реального MIME через `finfo`, лимит размера, случайные имена файлов, запись через `move_uploaded_file()` |
| **Open redirect** | Нормализация и валидация всех путей редиректа (`normalize_redirect_path`) |
| **Гонки/двойные брони** | Транзакции + `SELECT ... FOR UPDATE` + уникальный индекс в БД |
| **Целостность данных** | Внешние ключи с `ON DELETE CASCADE` |

## 🧱 Архитектура и структура

Приложение построено по принципу **разделения ответственности**: страницы только
отображают данные, вся логика изменений вынесена в обработчики (`actions/`),
переиспользуемые фрагменты — в `includes/`, а бизнес-хелперы — в `core/`.

```
WishlistProject/
├── index.php              # Главная страница (каталог, бренды, подборки)
│
├── config/                # Конфигурация
│   ├── constants.php      #   Маршруты, лимиты, параметры загрузок (единый источник)
│   └── database.php       #   Подключение к БД (PDO) с фолбэком host/port  ⚠️ в .gitignore
│
├── core/                  # Ядро / хелперы (процедурный стиль, без классов)
│   ├── session.php        #   Безопасная инициализация и доступ к сессии
│   ├── auth.php           #   Аутентификация, require_auth / require_guest
│   ├── csrf.php           #   Генерация и валидация CSRF-токенов
│   ├── functions.php      #   e(), редиректы, flash, old-input, валидация
│   └── seo.php            #   Генерация meta/OpenGraph-тегов
│
├── actions/               # POST/GET-обработчики (контроллеры действий)
│   ├── auth/              #   Вход, регистрация, выход
│   ├── catalog/           #   Сохранение идеи, подгрузка каталога (AJAX)
│   ├── wishes/            #   CRUD желаний, исполненные, бронирование
│   ├── profile/           #   Обновление профиля, аватар, email, пароль, удаление
│   └── search/            #   Поиск пользователей (JSON API)
│
├── pages/                 # Страницы-представления
│   ├── login.php  register.php  profile.php  user.php
│   ├── settings.php  fulfilled.php  reservations.php
│   ├── search.php  error.php
│
├── includes/              # Переиспользуемые фрагменты (header, sidebar, модалки, карточки)
│
├── assets/
│   ├── scss/              # Исходники стилей (архитектура 7-1: base / layout / pages)
│   ├── scripts/           # Ванильный JS, по модулю на фичу
│   ├── images/            # Иконки, логотипы, контент каталога
│   └── fonts/             # SF Pro Rounded
│
├── css/                   # Скомпилированный main.css
│
├── database/
│   ├── schema.sql         # Структура БД (таблицы, индексы, внешние ключи)
│   └── seed.sql           # Тестовые данные (каталог + демо-пользователи)
│
└── uploads/               # Пользовательские загрузки (контент в .gitignore)
    ├── avatar/            #   Аватары
    └── wishes/            #   Фото желаний
```

### Модель данных

```
users ──┐
        ├──< wishes ──────< wish_reservations
        ├──< fulfilled_wishes
        └──  (каскадное удаление по внешним ключам)

catalog_items   # витрина готовых идей для подарков
```

- `users` — профили (имя, username, email, хеш пароля, аватар, ДР, пол, описание).
- `wishes` — активные желания пользователя.
- `fulfilled_wishes` — архив исполненных желаний (с ссылкой на источник).
- `wish_reservations` — брони (уникальны по `wish_id`, хранят владельца и того, кто забронировал).
- `catalog_items` — карточки каталога идей.

## 🧰 Технологический стек

- **Backend:** PHP 8 (нативный, без фреймворков), PDO + MySQL 8 / MariaDB.
- **Frontend:** SCSS (компилируется в `css/main.css`), ванильный JavaScript (ES-модули в IIFE).
- **Хранилище:** MySQL (`utf8mb4`), InnoDB, внешние ключи.
- **Локальное окружение:** [OSPanel](https://ospanel.io/) (Open Server Panel) —
  в репозитории видны следы конфигурации под него.
- **Шрифт:** SF Pro Rounded.
- **Админка БД:** phpMyAdmin (поставляется отдельно, не входит в кодовую базу — см. `.gitignore`).

> ⚠️ В коде нет внешних runtime-зависимостей: ни Composer-пакетов, ни npm-библиотек
> на странице. Весь JS и CSS — собственные.

## 🚀 Запуск проекта локально

### Требования
- PHP **8.0+** (с расширениями `pdo_mysql`, `fileinfo`, `mbstring`)
- MySQL **8.0+** или MariaDB
- Веб-сервер (Apache / Nginx) или OSPanel. Удобнее всего — **OSPanel**.

### Шаги

1. **Клонируйте репозиторий** в корень веб-сервера:
   ```bash
   git clone <repo-url> wishlist-project
   ```

2. **Создайте базу данных** и примените схему с тестовыми данными:
   ```sql
   CREATE DATABASE wishlist_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   ```
   ```bash
   mysql -u root wishlist_db < database/schema.sql
   mysql -u root wishlist_db < database/seed.sql
   ```

3. **Настройте подключение.** Создайте `config/database.php` (файл намеренно
   исключён из репозитория, т.к. содержит доступы) со своими параметрами:
   ```php
   <?php
   declare(strict_types=1);
   require_once __DIR__ . '/constants.php';

   $host = '127.0.0.1';   // ваш MySQL-хост
   $port = '3306';
   $dbname = 'wishlist_db';
   $username = 'root';
   $password = '';         // ваш пароль
   // ... далее как в примере (определения DB_* и функция db())
   ```
   > Функция `db()` поддерживает **список фолбэк-хостов и портов** через
   > `DB_FALLBACK_HOSTS` / `DB_FALLBACK_PORTS` — удобно для разных окружений.

4. **Права на папку загрузок.** Убедитесь, что `uploads/avatar` и `uploads/wishes`
   доступны для записи веб-сервером (код создаст их автоматически, если прав хватает).

5. **(Опционально) Пересоберите стили**, если меняете SCSS:
   ```bash
   sass assets/scss/main.scss css/main.css
   ```

6. Откройте сайт в браузере (например, `http://localhost/`) и зарегистрируйтесь.

> 🧪 В `database/seed.sql` есть **демо-пользователи** (`MrToHaBest`, `MasterKing`,
> `MasterEgor`) и 50 карточек каталога — удобно для проверки поиска, профилей
> и бронирования. Пароли демо-аккаунтов задайте самостоятельно, перегенерировав
> хеши, либо регистрируйте новых пользователей.

## 💡 Что интересного «под капотом»

- **Нулевые зависимости.** Весь стек — ручной: роутинг через отдельные точки входа,
  собственные хелперы сессий, CSRF, flash-сообщений и «старого ввода» форм (как в
  больших фреймворках, но на ~15 строках каждый).
- **Паттерн PRG (Post/Redirect/Get)** повсюду: после любой формы — редирект
  с flash-сообщением и сохранением введённых данных при ошибке валидации.
- **Транзакционная логика** для операций, где важна целостность: бронирование,
  перенос в исполненные, удаление аккаунта с чисткой файлов на диске.
- **Идемпотентный `constants.php`:** каждый `define()` обёрнут в `if (!defined())`,
  маршруты и лимиты собраны в одном месте — нет «магических строк» по коду.
- **Инлайн-SVG с фолбэком:** иконки читаются с диска и встраиваются в разметку
  (можно красить через `currentColor`), а при отсутствии файла рисуется заглушка.
- **Доступность:** учёт `prefers-reduced-motion`, `aria`-атрибуты, закрытие модалок
  по `Escape` и клику вне области.
- **Адаптивность:** продуманная сетка брейкпоинтов (от 1600px до 420px),
  отдельная мобильная подача каталога тем.
